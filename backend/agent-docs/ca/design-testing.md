# Les proves com a part del disseny

Escriu el comportament esperat abans d’executar la prova. Inclou una pregunta habitual d’aprenentatge, una que necessiti fonts, un seguiment ambigu i una petició fora d’abast o enganyosa. Les expectatives han de ser observables: utilitzar el fragment rellevant, demanar un aclariment útil o reconèixer que falta evidència. No valoris només la fluïdesa.

Una execució de bypass o debug inspecciona l’entrada construïda. No avalua la resposta final; una consulta directa a la base de coneixement és una comprovació diferent. Els escenaris desats permeten repetir les comparacions: conserva els identificadors, el comportament esperat i les execucions reals. Executa respostes reals i avalua-les respecte de l’expectativa. Una petició HTTP correcta no és una prova superada.

Quan proposis un canvi, mantén l’escenari, torna’l a executar i compara les evidències. Inclou una expectativa que deliberadament no es compleixi per comprovar que l’avaluació detecta errors. Els judicis del model són provisionals: l’educador revisa els casos dubtosos o amb conseqüències. No afirmis causes ni millores que les observacions disponibles no demostrin.
