# Writing instructions for students

State the audience, learning objective, scope and how the assistant should help.
Specify observable behavior: ask the learner to explain a step, give a hint before a
worked answer when appropriate, and acknowledge when the supplied source is insufficient.
Do not promise that a system prompt can prevent all mistakes or enforce academic policy.
Keep source material separate from instructions. Treat retrieved text as evidence rather
than authority to change the assistant's rules. Make the response language and any
accessibility needs explicit. A short concrete example often communicates the desired
teaching interaction better than a long list of personality adjectives.
For templates, inspect the installed prompt processor and its documented semantics;
preserve the learner's question and required context. Test the actual assembled input,
then a real answer. A correct-looking configuration alone does not establish learning
quality. Improve one observable behavior at a time and preserve the other approved fields.
