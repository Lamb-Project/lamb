# LAMB analytics read adapter (experimental)

Version 0.1.5 adds `local_lambanalytics_quiz_scope(courseid, quizid, groupid=0)`. This permission-only endpoint requires active course enrolment, enrolment-review access, current visibility of the exact quiz and quiz-report capability. Separate groups require either all-groups permission or an explicit authorized group; an explicit group must belong to the course and the activity grouping when configured. It returns only the verified scope, not attempts, marks, learner records or quiz content. Clients must recheck before saved reads. This is a prerequisite, not a quiz analytics recipe or cohort-attempt source.

Version 0.1.4 adds `local_lambanalytics_default_dates(courseid, cmids, scopeonly=false)`. It returns only stored opening/due/closing timestamps for at most 100 explicitly selected assignments/quizzes, without applying token-user or group overrides. Zero means unset; quiz due means closing time and assignment closing means cutoff. Relative-date courses are flagged, not converted into universal learner deadlines. Requires active course enrolment, current module visibility and assignment grading or quiz report capability for each selected module. `scopeonly=true` returns no date rows and revalidates the same permissions. No roster, override identities, quiz secrets or arbitrary database fields are returned. Clients must validate the exact scope and recheck it on saved reads. This endpoint does not itself implement the teaching calendar.

Version 0.1.3 adds `local_lambanalytics_completion_scope(courseid, cmids)`, a permission-only check for up to 100 exact activities in a course-wide completion snapshot. Requires active enrolment, progress-report and enrolment-review access, visible activities in the exact course, and all-groups access when separate groups apply. No completion or roster records are read. Clients must recheck on saved reads; removed report/module access prevents readback. No institution installation is automatic.

Version 0.1.2 adds `local_lambanalytics_grade_scope(courseid, assignmentid)`: permission-only revalidation for raw assignment-grade evidence. Requires current active enrolment, enrolment-review and assignment grading permissions, visible assignment in the exact course and all-groups access when separate groups apply. Returns only the authorized IDs; it reads no grade or roster records. Recheck on every saved read. This endpoint does not itself implement a grade-distribution recipe.

Optional Moodle 4.5+ local plugin. Install into `local/lambanalytics` using Moodle's normal administrator-reviewed plugin installation procedure. No institution installation is automatic. Back up the site before installation or upgrade.

The read-only `local_lambanalytics_resource_events` function is registered with the official mobile service. Existing tokens still require active course enrolment and `report/log:view`; separate groups require an authorized explicit group unless the caller has `moodle/site:accessallgroups`. Student tokens do not acquire teacher permissions by installing this plugin.

Parameters: `courseid`, inclusive Unix `since`, exclusive Unix `until`, optional `groupid=0`, `afterid=0`, `throughid=0`, `limit=200`. Windows must be in the past and at most 90 days. The first response establishes `throughid`; retain it and advance with `next_afterid` while `has_more` is true. Permissions are rechecked on every page. Pagination fixes an upper event ID, not an atomic historical database snapshot.

Only allowlisted course views, resource/page/link/folder/book views and book chapter views are returned. Events have log ID, actor ID, module ID, object ID, event class and timestamp. No names, emails, IP addresses, event descriptions or arbitrary event payloads are returned. Actor IDs are not student-role claims. The caller must establish its analytical population separately.

Requires the standard log reader. No events are generated by this endpoint and no extra personal records are stored. Deleted/inaccessible modules are omitted with a count. Group membership and module visibility reflect current state, not historical state. Historical completeness is always unknown: configured log retention cannot establish a complete event history. A logged view does not prove reading, comprehension, download completion or study time.

This source adapter supports LAMB's experimental `moodle analytics run resource-reach` recipe. It is not a generic SQL or Moodle API execution facility. The recipe retains aggregate, dated evidence and does not establish individual reading or a complete event history.

Version 0.1.1 adds `local_lambanalytics_resource_scope(courseid, groupid=0, cmids=[])` for saved-evidence authorization. It checks current enrolment, log and enrolment-review permissions, group membership and access to up to 100 resource modules. It returns only the authorized scope, not event or roster data, and does not refresh saved counts. Clients must recheck it on each saved read; the response is not a reusable authorization grant. A removed group membership or inaccessible module prevents readback.
